# ExpoGuard AI — التسليم النهائي للوحدة المحلية

تاريخ التسليم: 13 أكتوبر 2026. المرجع الوظيفي: EXPOGUARD_CODEX_AI_HANDOFF (1).md الذي حدده صاحب المشروع.

نتيجة التحقق النهائي: نجحت 90 حالة اختبار دون إخفاقات أو تجاوزات، خلال نحو 60 ثانية، بما فيها كاشف النار والمسار القديم بالأوزان الحقيقية والعقود والمساعدات التشغيلية. التقرير في tests/reports/integration.json.

الوحدة جاهزة للمراجعة والتوصيل من جانب فريق الخادم بعد اجتياز الفحوص المحلية. هذا التسليم لا يعني اعتمادًا إنتاجيًا: الخادم الفعلي غير موجود هنا، ولم تُربط مزوّدات الرؤية العامة/الصوت، ولا توجد أدلة تشغيل معتمدة فعلية أو مجموعة تقييم مستقلة مكتملة.

## ما الذي يُسلّم؟

| الوظيفة | نقطة الدخول | الحالة |
|---|---|---|
| حريق ودخان | inference.fire_adapter.FireAnalyzer | يعمل بالأوزان المحلية؛ العقد v1 محفوظ |
| جودة الصور والإحداثيات | quality.image_quality وinference.coordinates | تحقق من الصورة والحدود والاتجاه، وأخطاء صريحة |
| العقد الموحد | core.multimodal.UnifiedAnalysis | v2 للصورة والنص والصوت؛ يتطلب اعتمادًا صريحًا لدى الخادم |
| صور عامة | vision.general.GeneralVisionAnalyzer | واجهة جاهزة؛ تحتاج مزوّدًا فعليًا، وتحافظ على كاشف النار |
| نص عربي | text.classifier.ArabicTextClassifier | قواعد محلية أولية، مع واجهة مزوّد لغوي اختيارية |
| صوت | audio.speech.SpeechAnalyzer | تفريغ ثم نفس مصنف النص؛ يحتاج مزوّد تفريغ |
| ربط تنبيهات | operations.correlation.correlate / rank_related | مساعد محلي خالص؛ لا ينشئ أو يدمج حادثًا |
| توصيات | operations.recommendations.recommend | استرجاع حرفي من دليل معتمد فقط؛ لا يُنفذ إجراءات |
| تقييم ومراجعة | evaluation.benchmark | أداء ومقاييس صور عند توفر وسوم بشرية؛ لا mAP حاليًا |
| اختبارات وجاهزية | run_tests وhandoff | تقرير اختبارات وبصمة مصدر وتقرير جاهزية محلية |

جميع مسارات Python المذكورة تستورد بإضافة ai. قبلها. تستخدم النماذج مجلد models/ المشترك. لم تُعدّل الأوزان أو يُجرَ تدريب جديد، ومسار JSONL القديم ما زال موجودًا ومختبرًا.

## Prompt 10 — Alert Correlation

المدخل AlertFacts يمثل حقائق أرسلها الخادم: alertId موجود بالفعل، والفئة، وobservedAt بمنطقة زمنية، والموقع والأصل والفعالية إن كانت موثوقة، وملخص البلاغ. aiConfidence اختياري ولا يدخل في حساب درجة الربط.

يفحص المساعد تطابق الفئة، وعدم تعارض zoneId/assetId/eventId، وقرب الزمن. افتراضيًا النافذة 300 ثانية، والعتبة .7، ويشترط موقعًا أو أصلًا مشتركًا موثوقًا لإصدار REVIEW_LINK. اختلاف معرفات موجودة عند الطرفين يمنع الاقتراح ولو كان النص متطابقًا. الموقع المفقود ليس موقعًا مطابقًا.

الدرجة الاسترشادية = .20 لتطابق الفئة + .35 للموقع/الأصل المشترك + .25×(1−فارق الزمن/النافذة) + .20×التشابه اللفظي. التشابه اللفظي Jaccard لكلمات النص بعد تسوية عربية بسيطة؛ ليس نموذج تشابه دلالي، ولا يضمن فهم المرادفات أو المعنى. الأوزان والعتبة أولية غير معايرة. تُرفق الإعدادات الفعلية وpolicyVersion والأسباب بالنتيجة.

النتائج REVIEW_LINK أو NO_SUGGESTION أو SAME_ALERT. الدرجة ليست احتمالًا ولا ثقة كشف ولا أمر دمج. rank_related يرتب قائمة تنبيهات دون كتابتها أو حذفها أو تغيير حوادثها. على الخادم تحديد المرشحين المناسبين للحدث والمستأجر والصلاحيات قبل الاستدعاء؛ هذه الدوال لا تدير العزل بين العملاء.

مثال محلي ببيانات تجريبية فقط:

```powershell
.\ai\.venv\Scripts\python.exe -m ai.operations.cli correlate --input ai/contracts/example-correlation.json
```

## Prompt 11 — Action Recommendations

القسم 20 من ملف التسليم يطلب الاستناد إلى Playbooks معتمدة ويمنع اختراع الإجراءات؛ لا يحتوي الملف نفسه إجراءات طوارئ أو كتالوج Playbooks. لذلك لا يتضمن التسليم دليلًا تشغيليًا مصطنعًا للاستخدام الفعلي.

يمرر الخادم IncidentFacts مع مرجع الحادث/البلاغ والأدلة وفئة وموقع وأصل موثوقين، وقائمة Playbook من كتالوج معتمد، ووقت now بمنطقة زمنية. النموذج يتطلب معرف الدليل وإصداره ومصدره وحالة اعتماده واسم المعتمد وتاريخ الاعتماد والصلاحية، ونطاق التطبيق، وخطوات لها مرجع قسم واضح.

تُستبعد DRAFT وREVOKED والأدلة المستقبلية والمنتهية وtestOnly. تُطابق الفئة ونطاق الموقع والأصل. إذا طابق أكثر من دليل، تعود AMBIGUOUS_PLAYBOOK دون اقتراح إجراءات حتى يختار الخادم/المراجع دليلًا واحدًا. لا تُختار نسخة «أحدث» بمجرد ترتيب نص رقم الإصدار.

عند توفر دليل وحيد صالح، تعود خطواته حرفيًا في proposals، مع sourceRef وsourceSection وplaybookVersion وplaybookSha256 وربط evidenceIds. لا توجد إعادة صياغة مولدة أو تلخيص قد يغير الإجراء. requiresHumanApproval=true دائمًا. لا تُعيّن فرق أو مهام ولا تُرسل إشعارات أو تُغلق حوادث.

عند غياب دليل معتمد: NO_APPROVED_PLAYBOOK. عند عدم انطباق الأدلة الموجودة: NO_APPLICABLE_PLAYBOOK. أمثلة الاختبار داخل الاختبارات مصطنعة وغير طارئة ولا تُثبت اعتماد جهة تشغيلية. حقول approvedBy وapprovalStatus ليست مصادقة بحد ذاتها؛ مسؤولية الخادم التحقق من الكتالوج والصلاحيات وحالة السحب قبل تمريره، وعدم قبول دليل من بلاغ زائر.

مثال دون أدلة، ينتج قائمة إجراءات فارغة:

```powershell
.\ai\.venv\Scripts\python.exe -m ai.operations.cli recommend --input ai/contracts/example-recommendation.json
```

## عقد التكامل والمسؤوليات

1. يتحقق الخادم من الصلاحيات وحجم الطلب والمصدر والموقع والزمن، ويُمرر بيانات موثوقة فقط. لا تتحول mentionedZone النصية إلى zoneId تلقائيًا.
2. يختار الخادم المسار والعقد v1 أو v2 صراحة. ملفات contracts/*.schema.json تصف الحقول، بينما بعض علاقات القيم والمراجع تُفحص برمجيًا كما يشرح contracts/README_AR.md.
3. OK دون مرشحات يعني عدم رصد مؤشر ضمن قدرات المسار، وليس شهادة سلامة. UNUSABLE وERROR لا يعاملان كصور/بلاغات آمنة ولا ينشئان OTHER احتياطيًا.
4. يحفظ الخادم النتائج ويدير idempotency باستخدام هوية الطلب/الصورة؛ معرفات det-N محلية داخل الطلب. معرفات الأدلة التشغيلية ينبغي أن تتضمن مرجع الطلب عند جمع مصادر متعددة.
5. ينشئ الخادم Alert ثم يمرر الحقائق الموثوقة إلى مساعد الربط؛ إنشاء Incident ودمجه النهائي ومنع التكرار من مسؤوليته.
6. يمرر الخادم دليل التشغيل المعتمد إلى الموصي. النتيجة مقترح للمراجعة، وليس إذن تنفيذ. القرارات التشغيلية والإشعارات وإثبات تسليمها كلها لدى الخادم/المشغّل.

الدوال محلية وليست خدمة HTTP. لا توجد مصادقة شبكية أو قاعدة بيانات أو endpoint منشور في هذه النسخة. أسماء حقول العقود الجديدة تحتاج مطابقة مع API الفعلي عند استلامه.

## التشغيل والتحقق من التسليم

من مجلد expo_modle وباستخدام بيئة Python الموجودة:

```powershell
.\ai\.venv\Scripts\python.exe -m ai.contracts.export_schema
.\ai\.venv\Scripts\python.exe -m ai.run_tests --integration --report ai/tests/reports/integration.json
.\ai\.venv\Scripts\python.exe -m ai.handoff --test-report ai/tests/reports/integration.json --output ai/reports/readiness.json
```

تُنتج الاختبارات تقريرًا يتضمن بصمة ملفات المصدر والمخططات. يتحقق تقرير الجاهزية من أن تقرير الاختبارات الكاملة ناجح دون تجاوزات ويطابق المصدر الحالي، ومن وجود الحزم والأوزان. تعديل الشيفرة/مخططات JSON بعد الاختبار يستلزم إعادة الاختبارات. هذه بصمة تحقق محلية وليست توقيعًا رقميًا أو تدقيق أمني مستقلًا.

READY_FOR_BACKEND_REVIEW تعني اجتياز متطلبات المراجعة المحلية فقط، وproductionReady يبقى false حتى تُستكمل متطلبات الجهات الخارجية. LOCAL_CHECKS_INCOMPLETE تعني أن تقرير الاختبارات قديم أو ناقص أو فاشل أو أن اعتماديات/أوزانًا لازمة غير متاحة.

إصدارات الحزم الفعلية وبصمة الأوزان تسجل في ai/reports/readiness.json. بيئة التشغيل الحالية اختُبرت؛ إنشاء بيئة جديدة أو حزمة نشر قابلة للتثبيت على خادم آخر لم يُختبر. requirements-contract.txt يثبت Pydantic فقط، ولا يُمثل تثبيت حزمة الرؤية كاملة. لا تنقل .venv بين الأجهزة بوصفها طريقة نشر مضمونة.

## ما يمنع الاعتماد الإنتاجي حاليًا؟

- لا يوجد خادم فعلي هنا لاختبار API والمصادقة والتكرار وتفاوض إصدارات العقود.
- مزوّدو الرؤية العامة والتفريغ واللغة غير مفعّلين وفق اختيار صاحب المشروع، واختباراتهم بدائل محلية.
- لم تُزوّد الوحدة بكتالوج إجراءات تشغيل معتمد؛ إجراءات فعلية غير متاحة.
- الصور الست التجريبية تنتظر مراجعة بشرية، واستقلالها عن التدريب مجهول؛ لا تُعلن دقة تشغيلية أو mAP أو إنذارات لكل ساعة كاميرا.
- لم تُعاير أوزان/عتبة الربط على أزواج تنبيهات موسومة؛ قد يفوت التشابه اللفظي المرادفات أو يربط بلاغات مستقلة في الموقع نفسه.
- قواعد العربية أولية، واختبارات الضبابية والحجب وحمل الكاميرات المتزامن والتثبيت على بيئة جديدة ما زالت مطلوبة.

## ترتيب الاستكمال مع فريق الخادم

استلام عقد API وكتالوج Playbooks موثوق؛ مطابقة العقود والإصدارات؛ تشغيل shadow mode؛ اختيار المزوّدين عند السماح بتفعيلهم؛ مراجعة البيانات وقياس الأداء؛ معايرة الربط وحدود القبول؛ ثم اعتماد التشغيل تدريجيًا بقرار فريق المشروع. لا يزيل نجاح الاختبارات المحلية أيًا من هذه المتطلبات.
